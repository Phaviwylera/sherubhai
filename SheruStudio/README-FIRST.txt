SAVED COOLDOWN / LIVE QUOTA CHECK

The app now distinguishes a saved wait from a newly rejected generation.
Install this update with Repair.cmd and choose the existing installation folder.
In Connections, save your own Hugging Face token and enable token authentication.
Save & test provider also refreshes live quota. Refresh live account quota can
repeat this read-only check without generating a video. Fine-grained tokens need
Billing > Read billing usage and payment method status for the quota-reading API.
Never put your token in a chat message or shared screenshot.

When the API confirms enough base GPU-seconds for the previously refused request,
the stale wait is cleared and an enabled automatic production worker resumes.
When allowance is insufficient, the provider reset time remains in force. Anonymous
mode cannot read account quota and retains the saved wait. It is not presented as
a newly measured quota. A quota refresh does not purchase or enlarge allowance,
rotate accounts, bypass limits, or enable paid overquota use. Generic rate-limit
windows are not cleared merely because GPU allowance is available.

The live check is cached for ten minutes during automatic waiting. API/network or
permission failures preserve the existing wait; details appear in logs. Waiting
status is shown in Automatic Production. Keep Studio open and the computer awake.

WHAT HAPPENS AFTER A FAILED REVIEW
1. Retry Tamil recognition without VAD and check with a stronger local ASR model.
2. Remix or rerecord the exact approved Tamil line over retained motion footage.
3. Check both clean speech and the final mixed clip. Never skip words or lower
   the pass threshold to declare success.
4. For visual/contact/cut failures, apply observed corrections and regenerate
   actual motion footage. The configured cloud pool can choose another model.
5. Retain every report, raw clip, repair and accepted shot. Unresolved quality
   queues another recovery cycle automatically. Quota failures wait for reset.

There are bounded retries (up to three local audio repairs per candidate and
up to eight scheduled recovery cycles). Persistent failures remain unapproved;
passing a transcript screen does not prove native delivery or mouth synchronization.
The local medium ASR weights download on first need and can run slowly on CPU.
Watch Automatic Production and its heartbeat, repair stages and retry timestamp.
